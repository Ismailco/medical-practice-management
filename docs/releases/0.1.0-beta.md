# Clinic Management 0.1.0-beta.1

## Added

This first open-source beta includes:

- Database-backed authentication with doctor/secretary capabilities.
- Administrative patients and appointments.
- Doctor-only consultations, immutable clinical note revisions, and addenda.
- Doctor-managed follow-ups with due-today, upcoming, and overdue views.
- Physician-entered prescription drafts, immutable issued history, duplication, replacement, and voiding.
- Server-generated A4 prescription PDFs regenerated from immutable issue snapshots.
- Guarded destructive test setup, browser E2E workflows, synthetic demo data, and PostgreSQL backup/restore scripts.

## Security architecture

Authorization is enforced on the server through capabilities and database-backed sessions. Clinical and
prescription responses are private and no-store; sensitive values are excluded from logs and audit
metadata. Clinical revisions, issued prescriptions, finalized items, and issue snapshots are immutable.
The integration and E2E suites require an explicit test environment, opt-in reset flag, and an isolated
`_test` database. These controls are engineering safeguards, not a compliance certification.

## Known limitations

- One clinic and one doctor instance; no multi-tenant or multi-doctor operation.
- English UI; Arabic/RTL PDF rendering is deferred.
- PDFs are regenerated from immutable issue snapshots; exact PDF bytes are not archived.
- No notifications, patient portal, public booking, billing, pharmacy, medication database, interaction
  checking, clinical recommendations, digital signatures, or signature/stamp images.
- Legal prescription formatting and compliance review remain deployment responsibilities.
- All demo and test fixtures are synthetic and must never be replaced with real patient data.

## Deployment warning

This is beta software and is not automatically compliant with any healthcare regulation. A real
deployment requires independent security and legal/compliance review, infrastructure hardening,
encrypted and restore-tested backups, access controls, and a documented retention plan. The browser
print workflow records PDF generation/request semantics only; it cannot prove that a physical printer
completed a job.
